#d 临时访问权
概念可以通过以下特征来定义：
* 所有权不转移：借用只是暂时把数据的访问权授予他人，数据的拥有者保持不变，借用结束后原所有者仍可使用该数据。
* 通过引用实现：借用通过 `&T`（不可变引用）或 `&mut T`（可变引用）来建立，而不是直接移动或复制数据本身。
* 借用规则约束：在同一作用域内，要么允许多个不可变借用（`&T`）共存，要么只允许一个可变借用（`&mut T`），二者不可同时存在。
* 生命周期有效：借用的引用必须在其指向的数据存活期间内有效，不能出现超出数据生命周期之外的悬垂引用。

#t 借用：用别人的东西要守规矩
通俗地说，借用（borrow）就像你向朋友借一本书：你可以拿来读，但不能在书上乱写乱画，更不能把书撕了带走。Rust 里的借用也是一样——代码想用某个值，不用把它的所有权搬走，而是「借」来用一下。借的时候有两条铁规矩：要么同时只有一个人可以「改着用」（可变借用），要么可以很多人一起「只看不改」（不可变借用），而且借来的东西不能比原主人活得还久（否则原主人的东西没了，你手里还拿着它，就成悬垂引用了）。这个规则的实现者就是借用检查器（Borrow Checker），它专门盯着代码里有没有违反规矩的「不速之客」。

#e 只读借用查看数据(正例)
你有一个由变量拥有的 `String` 值，你想把它传给一个函数来打印其长度，但希望之后仍能继续使用这个字符串。调用 `print_len(&s)` 时，函数参数类型为 `&String`，函数内部只能读取，不能修改。调用结束后，`s` 依然有效，可以继续被使用或再次借用。

特征对比：
- 所有权不转移：传递的是 `&s` 而不是 `s`，因此 `s` 仍是该 `String` 的所有者。
- 通过引用访问：函数参数是 `&String`，实参为 `&s`，符合借用的引用形式。
- 借用受作用域限制：借用只发生在函数调用期间，函数返回后借用结束。
- 借用后原所有者可用：调用 `print_len` 后，`s` 仍然拥有该字符串，后续代码可以继续访问。
- 遵循借用规则：整个过程中只有一个不可变借用，且没有可变借用同时存在。

#e 可变借用修改后归还(正例)
你需要临时修改一个变量持有的数值。在代码块中通过 `let y = &mut x;` 创建可变借用，并用 `*y += 1;` 修改 `x` 的值。离开该块后，可变借用自动结束，之后再次使用 `x` 依然合法，可以看到修改后的值。

特征对比：
- 所有权不转移：`y` 只是可变引用，`x` 的所有权始终在原变量手中。
- 通过引用访问：`&mut x` 是可变借用，符合借用的引用形式。
- 借用受作用域限制：借用只在 `{}` 块内有效，块结束即释放。
- 借用后原所有者可用：块结束后 `x` 可以被正常读取或再次借用。
- 遵循借用规则：该作用域内只有一个可变借用，且没有其他借用同时存在。

#e 同时多个不可变借用(正例)
你有一个由 `Vec` 持有的数据集合。你想同时读取其中两个元素并打印，因此创建了两个不可变引用 `&v[0]` 和 `&v[1]`。这两个引用可以同时存在，因为它们只读不写。使用这些引用后，`v` 仍可继续使用，也可以创建新的引用。

特征对比：
- 所有权不转移：`v` 仍然是集合的所有者，引用不拥有底层数据。
- 通过引用访问：`&v[0]` 和 `&v[1]` 都是不可变引用，符合借用的引用形式。
- 借用受作用域限制：引用在打印语句所在作用域内有效，之后可被释放。
- 借用后原所有者可用：打印后 `v` 仍然有效，可以继续读取或修改。
- 遵循借用规则：多个不可变借用可以并存，且没有可变借用，满足借用规则。

#e 移动而非借用(负例)
定义了一个 `String` 类型的变量 `s`，然后执行 `let s2 = s;`。这里 `s2` 直接绑定了 `s` 的值，原变量 `s` 的所有权被移动到 `s2`，之后 `s` 不再可用。表面上看，这和第 3 节正例中“让另一个变量使用这个值”的意图相似，但它没有使用引用 `&s`，而是发生了所有权转移，因此不是借用。

特征对比：
- 不转移所有权：违反。该现象将值的所有权从 `s` 移动给 `s2`，而非只创建对值的临时引用。
- 源变量仍可用：违反。`s` 在移动后无法再被访问，而借用后原变量始终可用。

#e 悬垂引用(负例)
编写了一个函数 `fn dangling() -> &String { let s = String::from("x"); &s }`，虽然使用了取地址符 `&`，看起来像是在返回一个借用，但 `s` 是函数内的局部变量，函数结束时 `s` 被销毁，返回的引用会指向无效内存。编译器会拒绝这种悬垂引用，它不满足借用对“引用生命周期不能超出被借用数据”的要求。

特征对比：
- 被引用的数据在借用期间保持有效：违反。引用返回时，局部变量 `s` 的生命周期已经结束，导致引用悬垂。
- 借用范围受编译器约束：违反。该引用试图逃逸出数据的作用域，没有处于合法的借用期限内。

#c 作用 判别借用是否合法
学会这个概念后，可以判断一段代码中“引用某个值而不拥有它”的操作是否被允许：能区分真正的借用（临时、只读或受限可变、不转移所有权）与非法操作（如悬垂引用、同时存在多个可变借用、借用期间移动所有权），从而指导编写通过借用检查器编译的 Rust 代码。

#c influence_to 借用影响面
借用机制会影响以下事物：

* 所有权系统：借用不转移所有权，允许在不交出数据所有权的前提下访问数据，影响值的使用方式和归属关系。
* 可变性约束：借用区分不可变引用（`&T`）和可变引用（`&mut T`），决定同一时刻允许存在多个读取者还是一个写入者，影响代码的可并发性。
* 借用检查器：借用规则是借用检查器进行静态分析的核心依据，影响引用能否通过编译。
* 引用的生命周期：借用的有效范围受生命周期约束，影响引用在哪些代码区间内可被安全使用，以及是否会形成悬垂引用。
* 内存安全保证：借用机制在编译期阻止数据竞争和悬垂指针，直接影响程序的内存安全特性。
* API 设计：函数参数和结构体字段中是否使用借用（以及借用类型）影响接口的抽象能力、调用约束和数据传递方式。
* 编译器诊断信息：违反借用规则会产生对应的编译错误，影响开发者对代码问题的定位和修复过程。

#c influenced_by 借用的约束条件
* 所有权（Ownership）：借用必须源自所有者，且借用的存在以所有权有效为前提。
* 可变性：在作用域内是否允许可变借用（`&mut`）或不可变借用（`&`）由变量的可变声明决定。
* 借用规则：同一时刻只能存在一个可变借用或任意多个不可变借用，且不可同时混用。
* 生命周期（Lifetime）：借用必须不超出被借用数据的存活范围，生命周期标注会影响借用检查。
* 作用域：借用发生在哪个代码区域，直接影响借用是否允许存在及其有效时长。
